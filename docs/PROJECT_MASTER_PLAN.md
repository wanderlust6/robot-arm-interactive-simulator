# 机械臂交互式仿真平台：项目总规划

> 文档定位：本文件是项目的执行级总规划，用于替代分散在 README、设计总档案、路线图和单次实验报告中的阶段性目标。
>
> 版本：v1.0（2026-10-24）
>
> 适用周期：未来 14 周；若时间不足，按第 4.7 节的 8 周 MVP 路径执行。
>
> 事实基线：本机 2026-10-24 实测。数学原型 143 项测试通过，桌面应用 102 项测试通过；Python 3.13.13、NumPy 2.5.4、SciPy 1.18.1、PySide6 6.12.0。

## 0. 一页结论

### 0.1 项目现在在哪里

项目已经跨过“能不能跑”的阶段：二维平面机械臂的运动学、数值逆运动学、关节限位、理想刚体逆动力学、笛卡尔路径规划、时间标定、奇异性指标、交互式桌面界面、曲线与实验包都已存在，并有 245 项自动化测试。

但项目还没有跨过“结论是否可信”的阶段：

- 多数合成路径上所有方法都 100% 收敛，基准没有区分度；
- 自适应 DLS 被证明与基线等价，已从界面移除；
- 限位规避是唯一显示出实用收益的候选，但存在关节步长尖峰；
- 风险标签的点级 Precision/Recall 只有 29.89%/63.64%；
- 在 10,152 个奇异扫描点中，有 4,968 个点出现参考分支不匹配，但末端误差仍然合格——“末端收敛”掩盖了“构型没有跟随”。

### 0.2 本期只做三件事

1. **把工程基线固化下来**：可安装、可测试、可复现、界面不阻塞。
2. **建立有区分度的基准**：让失败、分支偏差、限位余量和约束违反真正暴露出来。
3. **验证一个核心算法假设**：优先研究“固定末端路径下的分支意图保持与受控奇异穿越”，而不是继续增加算法选项。

### 0.3 一句话定位

> 在二维平面串联机械臂上，研究“给定同一条末端笛卡尔路径，如何选择关节构型”，并把这一研究做成可交互、可复现、可诊断的实验平台。

### 0.4 本期明确不做

- 三维模型、末端姿态约束、碰撞检测；
- 视觉、抓取、强化学习、完整自主系统；
- 实机控制与安全认证（除非实验室设备与接口已确认可用）；
- 电机/摩擦/柔性/接触动力学辨识；
- 以“功能数量”作为进展指标。

### 0.5 成功的定义

| 维度 | 最低成功标准（MVP） | 完整成功标准 |
|---|---|---|
| 工程 | 一条命令跑完全部测试；规划不阻塞界面；实验包可跨进程复现 | 有 CI、有包结构、有安装包、文档与实现一致 |
| 研究 | ≥6 类工况、≥4 种方法、≥30 个种子；报告成功/失败/分支/限位/耗时 | ≥10 类工况、独立测试集、统计检验、Pareto 分析、可解释选择规则 |
| 结论 | 至少一个可复现的正结果或明确的负结果 | 正结果通过独立测试集与消融实验；负结果解释清楚原因与边界 |
| 交付 | 可复现实验包 + 技术报告 | 论文初稿/竞赛演示 + 开源发布 + 5 分钟演示 |

### 1.4 三个瓶颈

1. **目标分散**：平台、奇异性研究、自动实验设计、算法推荐、自适应切换同时出现在文档中，但没有一个阶段性的唯一主目标。
2. **基准无区分度**：当前合成路径太容易，成功率指标饱和；真正有价值的分支偏差、限位余量、约束违反和耗时差异被平均值掩盖。
3. **工程结构拖慢研究**：每做一个新实验都要写临时脚本、手动整理 CSV；界面规划阻塞；实验记录不能自描述。

## 2. 项目定位与目标

### 2.1 定位

**研究对象**：二维平面串联机械臂，末端位置任务（暂不含姿态）。

**核心场景**：给定同一条末端笛卡尔路径、同一初始构型、同一关节限位与运动约束，不同逆运动学/构型策略会产生不同的关节路径。

**平台角色**：交互式仿真用于“看见现象、定位时刻、解释原因”；离线实验用于“产生证据、比较方法、验证假设”。两者共用同一套核心算法与结果协议。

### 2.2 目标层次

1. **工程目标**：一个结构清楚、可测试、可复现、界面流畅的桌面实验平台。
2. **研究目标**：回答“在什么工况下，哪种构型策略更合适，为什么”，并给出可复核的证据。
3. **成果目标**：形成可展示的软件、可复现的实验包、技术报告/论文初稿；是否实机验证由设备条件决定。

### 2.3 核心研究问题

> 在固定末端笛卡尔路径与统一约束下，如何构造有区分度的工况，公平评价逆运动学策略，并使“末端收敛、分支意图、运动连续性与约束满足”同时可解释？

拆成三个可执行问题：

- **Q1（诊断）**：当前 DLS 在哪些可复现工况下失败，或虽然末端收敛但关节构型不可接受？
- **Q2（方法）**：显式的分支意图与受控奇异穿越，能否在不牺牲末端精度的前提下改善构型一致性？
- **Q3（选择）**：基于工况特征的可解释选择规则，能否在独立测试集上优于任何单一固定方法？

### 2.4 研究假设（先写死，再实验）

> 以下阈值是本期目标，不是已证明结论；第 3 周基准确认后允许校准一次，之后冻结。

- **H1（分支意图）**：在跨奇异/近奇异路径上，分支感知策略相对基线将分支不匹配率降低 ≥50%，末端误差 ≤1e-5 m，最大相邻关节步长不超过基线的 1.5 倍。
- **H2（约束感知）**：在紧限位路径上，约束感知 DLS 将最小限位余量提高 ≥2°，且不产生 >0.05 rad 的相邻关节步长尖峰，末端误差 ≤1e-5 m。
- **H3（选择规则）**：在按工况族划分的独立测试集上，选择规则至少在一个主指标上显著优于最佳固定方法（95% 置信区间不跨 0），其他主指标退化不超过 10%。

### 2.5 范围与非目标

**本期范围**

- 二维、位置任务、串联转动关节；
- 1–12 连杆，重点 2–4 连杆；
- 运动学 + 理想刚体逆动力学；
- 路径级 IK、时间标定、约束检查；
- 离线批量实验 + 桌面交互 + 实验包；
- 分支意图、奇异穿越、限位规避、策略选择。

**本期非目标**

- 三维、姿态、碰撞、接触、摩擦、柔性、电机闭环；
- 视觉/抓取/RL/自主系统；
- 实机安全认证；
- 多机械臂/移动底座；
- 以“算法数量”或“界面控件数量”作为成果。

### 2.6 成功标准

**工程**

- 全新环境按 README 可在 10 分钟内跑起来；
- 一条命令跑完全部测试，CI 绿灯；
- 240 采样点规划在参考机器上 < 3 s；超过 1 s 的任务在后台线程运行，可取消、有进度；
- 实验包 v2 能在另一进程/另一台机器复现关键指标（容差内）。

**研究**

- ≥8 类工况、≥5 种方法、≥30 个种子/重复；
- 训练/验证/测试按工况族划分，测试集不参与调参；
- 报告均值、中位数、P95、置信区间、效应量、失败分类；
- 至少一个正结果通过独立验证，或一个负结果解释清楚“为什么无效、在哪些条件下有效”。

**交付**

- 5 分钟演示：常规路径 → 奇异穿越 → 紧限位 → 对比诊断 → 导出报告；
- 技术报告（10–20 页）与可复现实验包；
- README、架构说明、实验协议、局限说明齐全。

**依赖方向**：`ui → research → core`；`io` 被 `ui/research` 使用；`core` 不导入 Qt、不读写文件、不依赖全局状态。

**迁移策略**：不搞一次性重写。先在 `src/mechsim` 建新包，把核心模块逐步 `git mv` 过去，旧路径保留 re-export 兼容层；每迁一个模块，跑一遍全量测试。旧目录在 v0.3 之后再删除。

### 3.3 指标体系

| 指标 | 定义 | 单位 | 用途/注意 |
|---|---|---|---|
| `endpoint_error_max/rms/p95` | 实际末端与目标点距离 | m | 主指标；注意 1e-6 m 容差附近的数值噪声 |
| `success_rate` | 满足容差且无约束违反的点的比例 | % | 必须与失败分类一起报告 |
| `branch_match_rate` | 与参考关节路径同分支的点比例 | % | 两连杆用肘部符号；n 连杆用参考构型距离 + 阈值 |
| `branch_switch_count` | 路径中实际翻支次数 | 次 | 与“是否允许翻支”一起解释 |
| `reference_joint_deviation_max/rms` | 求解关节角与参考关节角的周期差 | ° | 仅在存在参考路径时有意义 |
| `joint_step_max` | 相邻路径点关节向量步长最大值 | rad | 关注尖峰，不只看均值 |
| `joint_path_length` | 关节路径长度和 | rad | 运动量代价 |
| `second_difference` | 离散二阶差分平方和/最大值 | rad | 平滑性代理，**不等同物理加速度** |
| `jerk_proxy` | 离散三阶差分或解析 jerk | rad/s³ | 有解析导数时优先解析 |
| `limit_margin_min` | 各关节到最近限位的角度 | ° | 紧限位场景主指标 |
| `duration` | 规划总时长 | s | 与时间最优性一起看 |
| `solve_time_p50/p95` | 单点求解耗时 | ms | 受机器影响，仅同机比较 |
| `constraint_violation_count` | 速度/加速度/力矩/jerk 超限计数 | 次 | 必须区分“不可行”和“未检查” |
| `sigma_min` | 雅可比最小奇异值 | — | 局部几何指标，不是安全限值 |
| `condition_number` | 条件数 | — | 与尺度有关，跨模型不可直接比较 |
| `time_optimality_gap` | 与 oracle/下界的相对差距 | % | 仅在有可信下界时使用 |

**报告规则**：

- 同时给均值、中位数、P95、最差值和样本数；
- 成功率必须与失败分类、不可达点数一起出现；
- 平滑性指标不得写成“物理加速度”；
- 计时结果标注机器与是否并行；
- 任何“更优”结论必须给出配对比较、效应量和置信区间。

**难度校准规则**：

- 如果基線在某个压力场景上仍然 100% 成功且没有明显分支/限位/耗时差异，先增加几何/约束难度（更靠近边界、更紧限位、更短时间），而不是加随机噪声制造失败；
- 每个场景必须写明“为什么这个场景能区分方法”；
- 训练/验证/测试按**场景族**划分，例如 S1–S5 训练、S6–S8 验证、S9–S10 测试；不能只用同族不同种子冒充独立测试。

### 3.6 实验与统计协议

1. **配对**：所有方法消费同一目标点数组、同一起始构型、同一限位、同一时间网格。
2. **重复**：随机初值/噪声场景 ≥30 个种子；确定性几何场景至少 3 种采样密度（61/121/241）。
3. **预注册**：每个实验在运行前写清主指标、成功判据、预期方向和停止条件。
4. **不调参测试集**：参数扫描只在训练/验证集；测试集只用于最终报告。
5. **统计**：配对差值用 bootstrap 95% CI 或 Wilcoxon signed-rank；报告效应量（Cliff's delta / Cohen's dz）；多重比较时说明校正方法。
6. **失败分析**：每个失败点必须有 `failure_code`；报告失败案例的路径位置、σ_min、限位余量和迭代数。
7. **负结果**：如果候选没有优势，保留报告并解释边界；不允许删除不利运行。
8. **环境**：记录 git commit、依赖版本、CPU、是否并行；计时类结论只在同机同设置下比较。

### 4.5 阶段 4：核心算法（第 8–10 周）

**目标**：只做一个主贡献，把它做扎实。

**主线（推荐）：分支意图保持 + 受控奇异穿越**

问题定义：

- 固定末端路径下，参考关节路径穿过 q₂=0 或 π；
- 当前 DLS 保持初始肘部分支，末端收敛但构型不跟随；
- 直接翻支会造成关节跳变；不翻支则偏离参考意图。

方法要点：

1. 分支意图表示：`none`（只要求末端）/ `reference`（给定参考关节路径或关键姿态）/ `keep-initial`（保持初始分支）。
2. 预判：由参考路径或 σ_min 预测即将穿越奇异；标记穿越区间。
3. 受控穿越：在穿越区间内减速/加阻尼，允许关节沿奇异流形通过；或在一个明确的切换点完成翻支，并记录切换时刻、σ_min、关节速度。
4. 验收：末端误差、分支匹配、切换段最大关节速度/加速度、切换前后连续性、总时长。
5. 失败回退：若穿越不可行，明确报告“无法在约束内保持分支”，不静默退回基线。

消融：

- 分支项开/关；
- 穿越触发阈值（σ_min）；
- 切换 vs 连续穿越；
- 步长限制/阻尼；
- 参考意图来源（参考路径 vs 初始分支）。

基线：

- 当前 DLS；
- 多初值/多分支 DLS；
- 加权/限位规避；
- 整段优化 oracle（小规模）。

**备选主线（若第 7 周评审认为算法风险过高）：约束感知策略选择**

- 特征：σ_min、限位余量、路径长度、曲率、采样密度、初值距离；
- 标签：在训练集上每种方法是否满足约束、主指标排名；
- 模型：浅层决策树/逻辑回归（可解释），不是黑箱；
- 验证：按场景族留出，报告选择规则的可解释性与失败案例。

验收：

- H1 或 H3 至少一个得到支持，或得到明确的负结果；
- 消融能解释“收益来自哪个组件”；
- 所有结论在独立测试集上复现；
- 不出现“末端误差合格但分支错误却被计为成功”的指标漏洞。

- 演示脚本：常规 → 奇异穿越 → 紧限位 → 对比诊断 → 导出；
- 复现包：固定 commit、依赖锁、示例数据、运行命令、预期输出；
- 发布：`v0.2.0` tag、许可证（待定）、可选的 PyInstaller 安装包；
- 复盘：哪些结论可对外说、哪些只能说“正在研究”。

验收：

- 另一台机器按复现包能得到报告中的关键数字（容差内）；
- 演示不依赖手工改数据；
- 文档中每个“已实现/已支持”都能在界面或测试中找到证据。

### 4.8 8 周 MVP 路径

如果 deadline 更紧：

| 周 | 内容 |
|---|---|
| 1 | 冻结、清理、CI、STATUS |
| 2 | PlanningService + 后台规划 |
| 3–4 | schema v2 + metrics + runner + 2 个场景族 |
| 5 | 基准 v1（S1–S6）+ 基线报告 |
| 6–7 | 分支意图方法 + 消融 |
| 8 | 独立验证 + 技术报告 + 演示 |

MVP 可以不做完整实验工作台、安装包、S8–S10；但**不能**跳过独立测试集和失败分类。

### 4.9 可选阶段 7：实机验证（第 15–18 周，条件触发）

仅当以下条件全部满足时启动：

- 有可安全限速、可急停的实验设备；
- 能读取关节角/末端位置/时间戳；
- 有低风险、短时长、可重复的轨迹；
- 仿真结论已经在独立测试集上稳定。

任务：低风险轨迹执行 → 仿真/实测对比 → 误差来源分析 → 模型修正 → 再次验证。

否则在报告中明确写“仅仿真验证”，不把仿真结论包装成实机结论。

## 6. 里程碑与 Go/No-Go

| 里程碑 | 时间 | 交付 | 通过条件 |
|---|---|---|---|
| M0 基线冻结 | 第 1 周末 | tag + STATUS | 测试全绿，状态可追溯 |
| M1 工程基线 | 第 3 周末 | pyproject + CI + 后台规划 | 安装/测试/取消/性能达标 |
| M2 实验协议 | 第 5 周末 | schema v2 + runner + 迁移 2 个实验 | 重跑一致，失败可分类 |
| M3 基准 v1 | 第 7 周末 | 场景集 + 基线报告 | ≥3 个场景有区分度 |
| M4 算法结论 | 第 10 周末 | 方法 + 消融 + 独立验证 | H1/H3 支持或明确负结果 |
| M5 发布候选 | 第 12 周末 | 工作台 + 实验包 v2 | 端到端演示可复现 |
| M6 交付 | 第 14 周末 | 报告 + 复现包 + tag | 另一台机器可复现 |

**Gate A（第 7 周）**：基准是否有区分度？

- 是 → 进入算法阶段；
- 否 → 停在基准重设计，不写新算法。

**Gate B（第 10 周）**：候选是否有可解释收益？

- 是 → 进入 UI 集成；
- 否 → 转为“诊断/选择规则/负结果”报告，不强行包装成改进算法。

**Gate C（第 12 周）**：工作流是否稳定？

- 是 → 发布候选；
- 否 → 缩减 UI 范围，交付 CLI + 报告。

- 输入/输出/单位/假设写清楚；

- 结果可复现（命令、配置、种子、版本）；
- 失败案例被记录，而不是被过滤。

## 11. 结论

当前项目最需要的不是更多功能，而是**一条能站得住的证据链**：

1. 用统一的工程基线保证“代码可信”；
2. 用有区分度的基准保证“实验能说明问题”；
3. 用一个明确的分支意图研究保证“结论有新意”；
4. 用可复现的实验包和报告保证“别人能验证”。

只要这四件事成立，平台、论文、竞赛演示和后续三维/实机扩展都有稳固的基础；反之，继续增加算法选项和界面控件只会放大不可信的部分。
