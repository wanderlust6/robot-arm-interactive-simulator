# 机械臂交互式仿真平台
**Interactive Robot Arm Simulation Platform**

一个面向机械臂奇异性问题的交互式仿真、算法比较与决策平台。项目从二维平面机械臂开始，目标不是单纯堆叠仿真功能，而是帮助用户回答一个具体问题：**面对不同奇异性工况、运动任务与约束，如何自动设计有代表性的实验，公平比较多种逆运动学方法，并选择当前更合适的算法？**

> **项目目标（暂定）**：自动生成测试工况与评价方案；直观展示不同逆运动学算法的运动表现和指标差异；在实验依据充分后，进一步实现面向任务与工况的算法推荐及仿真过程中的自适应切换。该目标仍会根据文献调研、实验结果和项目进展调整。
>
> **当前状态**：二维多段机械臂桌面仿真原型已支持模型参数编辑、末端目标交互、轨迹编辑与仿真、运动学/部分动力学曲线、实时奇异性诊断、数据导出和首版实验包。多种 IK 方法的对照实验目前主要位于离线数学原型与实验脚本中；自动实验设计和自适应算法选择尚未实现。详见[设计总档案](设计总档案.md)、[开发路线图](docs/DEVELOPMENT_ROADMAP.md)和[更新日志](CHANGELOG.md)。

## 要解决的核心问题

面对机械臂奇异性，不同逆运动学算法在末端跟踪精度、关节运动连续性、关节速度、构型分支、约束满足情况和计算开销等方面可能存在不同权衡。单一测试轨迹或单个指标不足以说明某种算法普遍更优，而让用户完全手动选择轨迹、参数、限制和评价曲线，也可能漏掉关键工况。

本项目计划围绕三个相互衔接的任务展开：

1. **自动设计实验**：依据测试目的生成代表性工况、轨迹、采样密度、初始构型与约束组合，并说明每个实验要验证什么。
2. **直观、公平地比较算法**：在一致的模型、目标轨迹、初始条件和评价规则下，对比候选算法的动画、曲线、定量指标与失败情形。
3. **推荐与自适应选择算法**：依据任务要求和当前工况，判断候选算法的适用性并给出可解释的推荐；在完成切换连续性与稳定性验证后，再探索仿真过程中的自动切换。

## 研究原则

- **问题驱动，而非功能堆叠。** 每项功能都应服务于实验设计、算法解释或决策验证。
- **不预设赢家。** 伪逆、阻尼最小二乘（DLS）、自适应阻尼 DLS，以及后续的加权或约束方法均作为候选对象；不预先认定某种方法最优。
- **多指标评价。** 至少根据任务需要考虑末端跟踪误差、求解成功率、关节运动连续性/速度、构型分支、约束违反情况和计算耗时，并明确指标的物理含义与局限。
- **实验条件可追溯。** 记录模型、算法及参数、轨迹、约束、采样策略、评价规则和结果，支持复现与公平比较。
- **区分物理限制与实验参数。** 真实模型约束、用户指定的任务要求和研究用阈值分别记录；缺少实机依据的数值应标明为仿真假设。
- **证据先于结论。** 动画和诊断标签用于解释结果，不能替代独立验证；研究用风险阈值不直接等同于生产或安全策略。
- **渐进开发。** 先用二维两连杆模型验证实验设计和算法比较流程，再根据结果决定是否扩展到更多连杆、动力学和三维模型。

## 当前已有能力

- 二维平面串联机械臂交互原型，支持 1–12 段连杆及相关参数编辑。
- 正运动学、雅可比矩阵、两连杆解析逆运动学、数值 IK 与连续候选解选择等数学原型。
- 轨迹编辑、仿真时间控制、关节/末端曲线、数据导出和首版实验包。
- 奇异值、雅可比条件数/秩、末端跟踪误差和关节限位等诊断呈现。
- 离线 DLS 与自适应 DLS 对比、参数敏感性、采样密度、初始姿态扰动、工作空间边界及路径风险分析脚本与报告。

已有实验显示，自适应 DLS 在部分平滑性代理指标上有改善，但在其他指标和工况上也可能退化，且计算开销可能增加；当前证据**不支持其整体优于基线**。已有测试也表明，末端位置求解收敛不等于复现指定关节轨迹或完成预期构型分支切换。具体结论和限制见各实验报告。

## 计划中的关键能力

| 能力 | 目标 | 状态 |
|---|---|---|
| 自动生成测试工况 | 生成奇异位形接近/穿越、不同采样密度、初值扰动、关节限位及组合约束场景 | 规划中 |
| 自动配置实验与评价 | 根据测试目的建议轨迹、采样、约束和评价指标，并解释选择依据 | 规划中 |
| 多算法统一对比 | 使用一致的条件运行候选算法，比较动画、曲线、指标与失败案例 | 已有离线实验基础，需系统化 |
| 算法推荐 | 根据任务偏好与测试证据，给出可解释的算法建议及权衡 | 规划中 |
| 仿真过程自适应切换 | 在切换连续性、约束和稳定性验证后，研究算法动态切换 | 后续研究 |
| 三维与更复杂模型 | 只有在核心问题和二维验证需要时再扩展 | 后续评估 |

## 开发路线

1. **整理实验基础**：梳理现有算法、数据、指标与已知局限，形成统一的实验配置和结果记录约定。
2. **建立自动实验设计**：围绕明确的测试问题生成代表性工况，检查可达性、约束合理性和场景覆盖，避免只生成容易通过的测试。
3. **统一算法比较**：建立共同输入、可复现运行、失败分类、多指标汇总和可视化对照。
4. **验证推荐策略**：定义不同任务偏好下的选择规则，与固定算法基线比较，并检查推荐是否能在独立工况中泛化。
5. **探索自适应切换**：研究运行中切换的触发条件、切换代价、轨迹连续性和失败回退；未验证前不把它作为默认控制策略。
6. **按证据扩展软件**：再决定如何组织 UI、是否增加更复杂机械臂模型、动力学或三维能力。

详细任务和完成标准见[开发路线图](docs/DEVELOPMENT_ROADMAP.md)。

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r "代码与仿真\桌面应用\requirements.txt"
.\.venv\Scripts\python.exe "代码与仿真\桌面应用\app.py"
```

## 贡献与变更原则

新增功能前，先说明它服务于哪个核心问题、需要什么证据验证，以及如何避免引入无法解释的实验变量。优先建设可复现的实验与明确的评价标准，而不是仅增加曲线、参数或面板。详见 [CONTRIBUTING.md](CONTRIBUTING.md)。
